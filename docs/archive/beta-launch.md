# 무료 베타 운영

수익 실험 순서: 월 3회 무료 → 추가 사용 관심 등록 → 소규모 크레딧팩 실결제 파일럿 → 재구매 확인 후 구독 검토. 현재 관심 등록만 제공하며 결제·유료 한도·광고는 켜지 않는다. 관심 등록은 지불 의사나 매출 실적으로 계산하지 않는다.

## 전체 상한

3일 공개 캠페인에는 `starts_at`~`ends_at`의 72시간 제한과 전체 모델 예약 $0.30 / Supadata 30크레딧 제한을 추가 적용한다. UTC 날짜가 네 번 포함되어도 캠페인 총량은 늘지 않는다. 종료 뒤 새 작업 claim과 공급자 예약이 차단되며 기존 결과 열람·의견 접수는 유지한다. 일일 한도 초기화는 한국 시간 오전 9시다.

`beta_limits`는 서비스 역할로만 수정한다. 초기 운영값은 OpenAI 보수적 예약액 일 $0.10 / UTC 월 $1, Supadata 요청 예약 일 10 / UTC 월 60크레딧, 동시 작업 1개다. 새 유료 공급자 요금제로 변경하지 않는다. 자막 공급자의 무료 한도는 모든 사용자와 개발자 테스트가 공유하며 별도로 남은 공급자 잔량을 확인한다. 공급자 결제 주기가 UTC 월과 다를 수 있다.

`reserve_beta_provider`는 공급자 호출 전에 전체 한도 행을 잠그고 예약한다. 모델 호출은 기존 사용자별 제한과 같은 트랜잭션에서 예약한다. 메타데이터·자막 각각 호출당 1크레딧을 예약하고, 실패·타임아웃도 환원하지 않는다. 공급자 소비가 불명확한 경우 과소 계상하지 않기 위한 보수적 처리다. 예약액은 청구액이 아니며 모델 토큰 사용량 기반 기록과 별도로 확인한다. 인프라 비용이나 다른 앱·수동 API 사용까지 차단하는 결제 상한은 아니다.

동시 한도에서 거절된 작업은 공급자를 호출하지 않고 실패 처리한다. 대기열 자동 재실행은 없으며 사용자 재시도는 기존 최대 3회 제한을 따른다. 공급자 사용량이 부족하면 운영자가 `enabled=false`로 중단하거나 크레딧 한도를 낮춘다. 잔량 확인 없이 한도를 높이지 않는다.

## 관측

`pnpm beta:report`는 연결된 DB의 집계만 읽는다. 이메일·자막·영상 주소·관심 등록 자유 입력은 출력하지 않는다. 가입, 변환 및 재사용은 기본적으로 개발자 계정을 제외하며 서비스 전체 비용은 개발자 사용도 포함한다.

화면 조회는 브라우저 탭·UTC 날짜·화면 종류별로 중복을 줄인 합계다. 고유 방문자 수나 정확한 개인별 전환 퍼널이 아니다. 조회 경로는 direct/search/social/other/internal만 저장하고 IP·전체 URL·검색어·방문자 식별자는 저장하지 않는다. DNT와 세션 저장소 차단은 측정 누락을 만든다. 봇/조작 유입도 가능하므로 매출 근거로 단정하지 않는다. 동작·저장 항목은 `/beta`에 안내한다.

## 첫 2주

1. 전체 한도와 배포 동작을 확인하고 집계 기준선을 기록한다.
2. 소규모 대상에게 무료 베타를 공유한다. 외부 커뮤니티 글 게시는 사용자 요청이 있을 때 진행한다.
3. 첫 변환 성공, 다른 날짜의 재사용, 무료 한도 소진, 추가 변환 신청을 확인한다. 표본과 실제 노출량을 함께 본다.
4. 추가 사용을 원하는 1~3명과 팩 크기·가격을 검증한다. 실결제와 환불을 처리할 운영 절차·정산 수단이 갖춰진 뒤 판매한다. 현재는 결제 링크나 가격을 노출하지 않는다.
5. 실패율 상승이나 예산 소진 시 유입 확대를 멈추고 원인을 해결한다. 가격·성공률·방문량의 임의 수치를 시장성 판정 기준으로 사용하지 않는다.

검증: `pnpm lint`, `pnpm build`, Deno worker tests, `scripts/test-beta.sql`의 롤백 기반 DB 검증. 모델/API 실제 변환을 호출하지 않고 차단·권한·예약 원자성을 검증할 수 있다.
