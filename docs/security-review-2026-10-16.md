# 공개 베타 보안 점검 — 2026-10-16

## 수정

- 저장형 XSS 경로: 인증 사용자는 Supabase RPC를 직접 호출해 `content_html`에 임의 HTML을 저장할 수 있었다. 공개 페이지·편집 초기값·글 API 응답은 항상 정제한 Markdown으로 HTML을 다시 생성한다. DB 트리거도 HTML 캐시에 이스케이프한 텍스트만 저장한다. 기존 데이터도 렌더 시 정제하므로 원시 캐시를 신뢰하지 않는다.
- DB 입력 제한: 직접 RPC 호출의 URL을 표준 YouTube 주소와 영상 ID로 제한하고 글 제목·본문·슬러그 등의 길이를 검사한다. Next.js API 우회로 제한을 피하지 못하도록 DB에도 검증한다.
- 권한 축소: 공개 읽기 역할에서 작성자·작업 식별자와 HTML 캐시 조회 권한을 제거한다. 인증된 글 API는 본인 글만 조회한다. 공개 글은 기존 익명 전용 클라이언트로 읽는다. 레거시 RPC와 내부 제한 함수의 직접 실행은 차단한다.
- 변경 요청 출처: `/api` POST/PATCH/DELETE는 같은 Origin만 허용하며 교차 사이트 요청을 세션 확인 전에 차단한다. Next.js Server Actions의 기존 출처 검사도 유지한다.
- 요청 본문: Content-Length와 실제 스트림 바이트 양쪽을 검사한다. 길이 헤더 없는 큰 요청, JSON이 아닌 요청, 배열·null 등을 거절하며 읽기는 5초 후 취소한다.
- 반복 호출: DB에서 사용자별 글 수정 30/분, 작업 생성 10/분, 재시도 5/분, 관심 등록 3/분을 제한한다. 조회 계수는 서버 전용 RPC로 옮기고 조회·방문 집계 각각 서비스 전체 120/분으로 제한한다. 내부 버킷은 7일 뒤 정리한다. 실패 RPC는 트랜잭션이 롤백되므로 이 제한은 모든 잘못된 시도나 네트워크 폭주를 계수하는 방화벽이 아니다.
- 브라우저 보호: CSP의 외부 스크립트·이벤트 속성·object·프레임·base 제한, nosniff, DENY 프레임 정책, no-referrer, 권한 정책, HTTPS HSTS를 적용한다. 비공개 화면과 API에는 no-store 정책을 지정한다.
- 운영 의존성: 빌드/코드 생성 도구인 shadcn을 개발 의존성으로 이동한다. Tailwind CSS 빌드 사용은 유지한다.

## 검증과 한계

보안 재현 테스트는 교차 Origin, Content-Length 없는 초과 스트림, 잘못된 JSON, 악성 Markdown, SSRF 주소와 로그인 리다이렉트를 검사한다. `scripts/test-security.sql`은 합성 사용자·글로 HTML 직접 삽입, 다른 사용자 접근, 공개 열 권한, 직접 RPC 제한과 레거시 실행 차단을 검증하고 롤백한다. 테스트는 외부 모델을 호출하지 않는다.

운영 의존성 감사는 경고 0건이었다. 전체 개발 의존성에는 [braces의 미패치 재귀 깊이 문제](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)가 남아 있다. 개발 도구 경로이며 웹 요청에서 사용자 패턴을 전달하는 코드가 없다. 이동은 취약점 자체의 패치를 의미하지 않는다. 추적 파일의 키 패턴과 브라우저 번들의 실제 비밀키 값 검사에서는 일치가 없었다. 이 검사는 외부 계정·전체 Git 이력의 포렌식 감사는 아니다.

Next.js 16.4의 PPR 정적 스크립트를 유지하기 위해 CSP에는 `unsafe-inline`이 남는다. 따라서 nonce 기반의 엄격한 CSP라고 부르지 않는다. XSS 차단의 주 경계는 Markdown 정제와 DB 입력 처리이며 CSP는 추가 방어다. 브라우저 Origin은 봇의 신원을 증명하지 않는다.

3일 캠페인의 비용 사전 예약과 일/월/총량 제한, 만료 시 차단은 유지한다. 호스팅 DDoS·공급자 계정 탈취·관리자 기기 침해까지 막는 보장은 없다. 외부 침투 테스트나 운영 계정 MFA 확인은 수행하지 않았다.

공개 모집은 여전히 긱뉴스 로그인 및 외부 사용자 로그인 경로 준비가 필요하다. 현재 커스텀 SMTP가 없으며, 익명 로그인 기능은 이번 보안 작업에서 활성화하지 않는다.
