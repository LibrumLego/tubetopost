# 안정성 개선과 검증 (2026-10-14)

`0005_reliability.sql`, `0006_job_recovery_schedule.sql`을 원격 DB에 적용하고 최신 Edge Function을 배포했다.

## 복구와 재시도

매분 실행하는 pg_cron이 1분 이상 시작되지 않은 queued 작업과 5분 lease가 만료된 진행 작업을 `JOB_TIMEOUT` 실패로 바꾼다. 로그인한 사용자의 조회에서도 복구한다. 실패 상세 화면에서 최대 3회 수동 재시도할 수 있다. 자동 재실행은 하지 않는다.

각 실행에 별도 attempt ID를 발급한다. 상태 변경과 완료 RPC는 현재 attempt와 유효한 lease를 확인한다. 복구 후 늦게 끝난 이전 실행이 결과를 덮어쓰거나 사용량을 중복 차감하지 못하도록 한다. `after`와 `waitUntil` 자체는 영속 큐가 아니다.

## 생성과 비용

개요와 SEO는 strict JSON Schema로 생성하고 로컬에서도 검증한다. 거절·잘린 응답·스키마 오류를 구분하고 실패 단계를 기록한다. SDK 자동 재시도는 끄며 JSON 검증 재시도도 예산에 포함한다.

- 사용자당 동시 작업 1개, 월 실행 시도 최대 30회.
- OpenAI 예약 비용: 실행당 $0.05, 같은 작업의 재시도 합계 $0.10, 사용자 월 합계 $1.
- 호출 전에 입력 UTF-8 바이트와 최대 출력 토큰으로 보수적으로 비용을 예약한다. 예약 비용은 실제 청구액이 아니며 실제 토큰 사용량은 별도로 기록한다.
- 생성은 120초 기준으로 호출 전·완료 전 시간을 확인한다. 진행 중인 호출이 즉시 취소되는 것은 아니다.
- Supadata metadata의 실제 영상 길이로 20분 초과를 거절한다. 길이를 확인하지 못하면 생성하지 않는다. 자막은 최대 50,000자이며 너무 짧은 원문도 생성 전에 거절한다.

Supadata 경로는 metadata와 native transcript를 각각 요청한다. OpenAI 예약 비용에 Supadata 크레딧은 포함되지 않는다. 모델 변경 시 strict schema 지원과 입력·출력 단가 설정을 함께 확인해야 한다.

## 편집 저장

제목·본문·공개 여부를 1.5초 debounce 후 함께 저장하며 요청을 직렬화한다. 저장 중 다시 편집한 최신 값도 다음 요청으로 반영한다. 서버 revision이 다르면 409로 거절하며 초안은 화면에 남긴다. 최신 글을 불러오기 전에 필요한 초안을 복사해야 한다. 네트워크 실패에는 저장 재시도 버튼을 제공하고 미저장 변경이 있으면 페이지 이탈을 경고한다.

## 품질

새 본문의 중복 제목 H1을 제거한다. 영상 길이에 따라 섹션 수를 줄이고 섹션마다 겹치지 않는 자막 범위를 사용한다. 모델이 만든 링크 대신 실제 자막 timestamp에 맞춘 영상 링크를 붙인다. 사실·수치·고유명사 추가를 금지하고 농담과 비유를 실제 사건으로 서술하지 않도록 지시한다.

이 규칙이 사실 정확성을 보장하지는 않는다. 초기 생성 결과의 반복 설명과 비유의 사실화가 발견되어 지시와 자막 분할을 강화했다. 마지막 품질 조정은 자동 테스트로 검증했으며 월 변환 할당량을 소진하여 조정 후 추가 실제 생성은 하지 않았다. 공개 전 원문 대조가 필요하다. 기존 글을 일괄 수정하지 않았다.

## 검증

| 영상 | 실제 결과 |
|---|---|
| TED `arj7oStGLkU` | 실패 작업 재시도 후 글 생성 완료 |
| TypeScript `zQnBQ4tB3ZA` | 글 생성 완료 |
| 짧은 영상 `jNQXAC9IVRw` | SOURCE_TOO_SHORT, OpenAI 예약 비용 0 |
| 긴 강의 `rfscVS0vtbw` | VIDEO_TOO_LONG, OpenAI 예약 비용 0 |

실행 중 다른 작업 요청의 409 거절을 확인했다. 브라우저에서 저장 응답을 지연시켜 최신 편집 보존, 네트워크 실패 후 재시도, revision 충돌 안내를 검증했다. 시험 TED 글은 비공개로 복원했다.

Deno 테스트 19개, lint, TypeScript를 포함한 프로덕션 빌드가 통과했다. 원격 DB에서 합성 데이터 트랜잭션으로 복구·권한·예산·중복 완료·revision을 검증하고 rollback했다. cron 실행 성공을 확인했다. 최신 배포 인증 probe는 인증 없음 401, 올바른 secret과 잘못된 작업 ID 400이었다.

`scripts/test-reliability.sql`은 적용된 DB에서 서비스 권한으로 실행한다. 자체 트랜잭션의 끝에서 rollback하며 실제 외부 API를 호출하지 않는다.
